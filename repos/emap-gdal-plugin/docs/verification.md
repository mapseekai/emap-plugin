# 首版验证记录

日期：2026-09-18。环境：macOS arm64、Node 22.23.1、npm 10.9.8、本机 Google Chrome（Playwright 启动）。
依赖：@mapseekai/gdal3.js 2.8.2、@mapseekai/emap 0.13.0、单实例去重的 cordis 4.0.0-rc.10。

在管理仓库执行 `npm run verify`，退出码为 0，覆盖以下内容：

| 验证 | 结果 |
| --- | --- |
| 单仓库脚手架 | 通过；包含名称校验、dry-run、重复保护、清单登记、无嵌套 Git、生成插件编译和生命周期测试 |
| TypeScript | 通过；包含公开 API 正反类型用例和演示页 |
| 单元与生命周期 | 4 个文件、28 项测试通过 |
| 构建 | ESM、声明文件、内联源映射内容与 GDAL JS/WASM/data 资源生成成功 |
| npm 包检查 | 导出路径、自引用导入、资源与许可证完整性通过 |
| 真实浏览器集成 | 28 项断言通过，不是用 mock 代替 WASM |
| Vite 演示页 | 真实选择文件、生成 .ovr、结果与保存链接验证通过 |

真实 GDAL API 套件创建 21 个 Worker，全部 21 个终止；该串行测试的峰值为 1。
测试输入是上游项目的合成 `overview-uint16.tif`（64×48 UInt16），不是用户的生产影像。
指定 2/4/8 倍层级得到 32×24、16×12、8×6；平均重采样输出 .ovr 为 2850 bytes。
验证了原图字节不变、UInt16 数据类型保留、GDAL 重关联 .ovr、gdaladdo 重建及自动层级生成。
还验证了栅格重投影、矢量/Shapefile 往返、伴随文件齐全、栅格化、坐标转换、像素定位和实际驱动查询。
emap 通过公开 GeoTIFF 接口识别原始层与三个金字塔层，并成功读取金字塔像素、创建地图图层。
浏览器明细由每次运行更新到 `test-results/browser/report.json`（不提交）。

## 问题修复与边界

测试捕获并修复了容量为 1 时的队列释放时序问题：现在先释放名额，再完成公开 Promise。
测试覆盖 Worker 初始化取消、运行失败、异常进度回调、超时、卸载、重启与跨地图隔离。
npm 10 安装阶段发生的可选 Vitest peer 解析异常由项目级 `.npmrc` 处理，未更改全局 npm 设置。
`npm audit --omit=dev` 当前报告本插件 production 依赖 0 个已知漏洞；这不覆盖开发工具链或宿主自行安装的 emap/其他 peer，也不代表完整安全审计。
原 emap 工作树仍干净；gdal3.js 原有未提交修改与任务开始时一致，未编辑这两个项目的源文件。

未验证的项目：Safari/Firefox、GB 级生产影像的性能/峰值内存、所有 GDAL 驱动与选项组合、所有 NoData/mask/压缩组合。
不宣称桌面完整 GDAL 能力、原地内部金字塔或 XYZ 切图能力。
插件是外部独立包，未自动写入原 emap 的默认 preset 或修改其依赖；宿主需显式安装并注册。
本次仅初始化两个本地 Git 仓库并生成源代码，未提交、推送、创建远端或发布 npm。
